# BB V.G. — актуальный контекст проекта

Этот файл хранит только действующие договорённости. История решений находится в
`PROJECT_CHANGELOG_RU.md`.

## Пользовательское поведение

- Одно подтверждённое нереферальное событие даёт не более одного первичного
  уведомления каждому разрешённому получателю.
- Telegram и VK используют одну стабильную идентичность wheel-event; точное
  время получения может различаться из-за независимых API.
- Redirect Telegram-канала не создаёт второй источник рейтинга: настроенное
  имя остаётся каноническим, а фактический redirect используется только в URL.
- Реферальные и предположительно реферальные колёса сохраняются во внутреннем
  состоянии, рейтинге и автоучастии, получают одну первичную Telegram-карточку
  и один общий итог по трём production-аккаунтам; VK-доставка отключена.
  Классификация использует явный текст публикации/BetBoom-страницы и историю
  того же идентификатора. История без нового прямого доказательства даёт только
  `suspected_referral`; временный `unconfirmed` не является окончательным
  отказом, а `referral_ineligible` допустим только по явному ответу BetBoom.
- Автоучастие выполняется независимо от настройки пользовательских итоговых
  уведомлений.
- Результаты двух BetBoom-аккаунтов Вячеслава объединяются в одно короткое
  сообщение. Технический timeout или `unconfirmed` не является пользовательской
  неудачей.
- Ошибка preflight, сессии или браузерной попытки одного BetBoom-аккаунта не
  блокирует запуск остальных аккаунтов и независимого recovery.
- Уведомление о колесе содержит переходы «Активные колёса» и «Главное меню».

## Production

- Источник истины — `main`.
- Оперативное публичное состояние Monitor и browser-results хранится в
  `runtime-state`; writers используют CAS с повторным чтением и семантическим
  merge, а Control Center читает тот же authoritative snapshot.
- Единственный Control Center запускается командой
  `python notification_button_recovery.py` на exact SHA из
  `control_center_release.txt`; validator и live-job используют один commit.
- Control Center создаёт смену-преемника только после успешного завершения.
  Отмена, вытеснение или ошибка не запускают recovery из завершающегося run;
  почасовой schedule страхует разрыв без каскада взаимных отмен.
- Плановая замена Control Center принадлежит только изменению
  `control_center_release.txt` в `admin-bot.yml`; `validate-current.yml` не
  запускает второй дублирующий Control Center после того же push.
- Validation и live-job смены используют shallow checkout exact release SHA.
  Полная история постоянно растущих runtime-коммитов не загружается перед
  запуском единственного Telegram `getUpdates` consumer.
- Временный GitHub API `403 rate limit` при стартовой записи heartbeat не
  блокирует Telegram consumer: запуск использует проверенную локальную
  encrypted-копию exact release SHA, а удалённый heartbeat повторяется после
  восстановления API. Фоновый snapshot панели обновляется раз в минуту.
- Монитор не вызывает Telegram `getUpdates`.
- Неуспешная смена Monitor не перезапускает себя. Controlled recovery выполняет
  только `monitor-watchdog.yml` после проверки heartbeat и прогресса.
- Коррелированный transient-сбой `telegram.me` по нескольким источникам
  повторяется по сбойному подмножеству и не превращается в набор независимых
  шестичасовых карантинов. Диагностическое уведомление об источнике требует
  повторного подтверждения. Более новый полный проход Monitor подтверждает
  восстановление только primary-ошибок старого transport snapshot.
- Опциональный AI-инспектор и чтение защищённой конфигурации уведомлений не
  могут прервать детерминированную health-проверку до сохранения состояния.
  Их сбой фиксируется отдельным finding, а остальные инциденты продолжают
  открываться и закрываться по актуальным runtime-снимкам.
- VK-уведомление вызывается напрямую monitor-runtime; ручной workflow является
  fallback.
- Перед крупным удалением или изменением workflow создаётся неизменяемая
  backup-ветка от точного `main`.
- Успешный merge не считается deploy без свежих heartbeat панели и монитора.

## Границы

- Mini App, Cloudflare Worker и D1 архивированы и не изменяются без отдельной
  прямой команды.
- Runtime JSON, encrypted state и delivery ledger нельзя удалять как мусор.
- Raw Telegram ID, chat ID, токены и приватные данные запрещены в публичном Git.
- При сомнении файл сохраняется до подтверждения импортами, workflow, тестами,
  state-owner и историей.
